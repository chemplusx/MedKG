From raw biomedical data to a unified graph

As documented in Molecular Diversity (Vol. 29, 2025), MedKG integrates 35 curated sources into 34 node types and 79 relationship families. Each domain folder encapsulates acquisition, cleaning, relationship expansion, and persistence logic so the graph stays current through a Continuous Integration/Continuous Update workflow.

Pipeline stages

Core orchestration steps

  1. Acquisition: download, parse, and validate domain-specific datasets (CSV, TSV, XML, OBO, JSON).
  2. Normalisation: align identifiers, clean synonyms, map ontologies, and enrich nodes with curated metadata.
  3. Graph assembly: create nodes/relationships, ensure uniqueness, and batch load into Neo4j via official drivers.
  4. Quality checks: evaluate relation totals, duplicate ratios, and type coverage using summary CSVs in `data/`.
Modular scripts per source Provenance retained in properties Deterministic filtering for high-confidence edges
CI/CU pipeline

Continuous updates backed by the published workflow

The MedKG ingest stack runs as a Continuous Integration/Continuous Update (CI/CU) process, automatically refreshing source drops, harmonising identifiers, and redeploying to Neo4j. The journal article details how scheduled jobs, validation notebooks, and regression checks ensure the knowledge graph never drifts out of date.

Running the pipeline

MedKG scripts are built for reproducibility, with environment-controlled data directories and Neo4j connection helpers.

Step-by-step

Environment & common pattern

  1. Set the `MEDKG_DATA` environment variable to point at `MedKG/data` or your custom location.
  2. Inspect the ETL script in the relevant folder to confirm required inputs and connection credentials.
  3. Run the script directly; most use the official Neo4j Python driver with parameterised Cypher queries.
  4. Validate counts using CSV summaries (`total-relations.csv`, `triple_uniqueness.csv`) or Neo4j introspection queries.
# Example: biomarkers ETL
export MEDKG_DATA=/Users/me/MedKG/data
python biomarkers_data/etl_biomarkers.py
Best practices

Operational guidance

  • Configure Neo4j credentials once in each script (`GraphDatabase.driver(uri, auth=...)`).
  • Use the provided `data/relations.csv` to verify expected relation types before loading.
  • For large imports, wrap writes in transactions and leverage `neo4j` driver sessions with batching.
  • Update scripts to target remote clusters by editing the URI (defaults to `bolt://localhost:7687`).
# Build a composite index (optional)
CREATE INDEX node_name_index IF NOT EXISTS

Graph access via medkg-api

A Go application server wraps Neo4j queries with REST endpoints, websocket streaming, and a ready-to-ship UI.

Capabilities
  • Search & autocomplete: full-text indices across drugs, diseases, proteins, pathways.
  • Graph traversal: multi-hop path exploration via `GetNetworkGraphForId` query helpers.
  • Schema introspection: `/labels`, `/edges`, and label-specific metadata endpoints.
  • Visual client: responsive Materialize UI in `medkg-api/static` with stats, search, and interaction filters.
Run locally 
cd medkg-api
go mod tidy           # install dependencies
go run main.go        # serve on http://localhost:5000

# REST docs
http://localhost:5000/swagger
http://localhost:5000/api-docs

# Web UI
http://localhost:5000/home

Deployment templates include Docker-friendly configuration and websocket streaming under `medkg-api/websocket`.
