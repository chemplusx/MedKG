Integrated biomedical knowledge sources

MedKG harmonises clinical datasets, ontologies, and molecular knowledge into a single graph. Published findings in Molecular Diversity report a total of 35 curated sources spanning 34 node types and 79 edge families, ensuring drug discovery workloads have comprehensive coverage.

Source catalog

Descriptions are derived from ETL scripts and data files checked into the repository. The full knowledge graph comprises 35 sources as detailed in Kumari et al., 2025.

Source Folder What it adds Key entities & relations Notes
DrugBank drugbank_data/ Drug metadata, pharmacology, transporter/enzyme interactions, indications and contraindications. Nodes: `Drug`, `Protein`
Relations: `IS_AN_INDICATION_FOR`, `IS_A_CONTRAINDICATION_FOR`, `TARGETS`, `HAS_TRANSPORTER`, `HAS_ENZYME`		 Requires DrugBank licence; ETL scripts expect JSON exports under data/.
Target Discovery (TTD) tdd_data/ Associates drugs, targets, and diseases using curated therapeutic annotations. Relations: `TARGET_DISEASE`, `TDD_DRUGS`, `TDD_TARGETS` Scripts generate Neo4j loads via custom Cypher queries.
ChEBI chebi/ Chemical entities of biological interest with roles, definitions, and hierarchies. Nodes: `Compound`
Relations: `HAS_ROLE`, `IS_A`, `HAS_PARENT_HYDRIDE`, `IS_SUBSTITUENT_GROUP_FROM`		 ETL handles XML/TSV inputs, resolves synonyms, and maintains ChEBI accessions.
Human Phenotype Ontology human_phenotype/ Phenotypic abnormalities with mappings to diseases and experiment factors. Nodes: `Phenotype`
Relations: `HAS_PARENT`, `MAPS_TO`		 Uses OBO/JSON exports located in data/hp.json.
Uber-anatomy ontology (UBERON) uberon/ Anatomical structures, tissues, and organ systems. Nodes: `Tissue`
Relations: `HAS_PARENT`		 Enables tissue-level stratification of biomarkers and diseases.
FoodOn foodon/ Food ontology terms to link dietary factors with health outcomes. Nodes: `Food`
Relations: `IS_A`, `HAS_PARENT`		 XML samples included under data/foodon-sample.xml.
GWAS Catalog gwas-catalog/ Genome-wide association studies connecting traits, variants, and diseases. Nodes: `GWAS_study`, `Experimental_factor`
Relations: `STUDIES_TRAIT`, `MAPS_TO`		 Integrates with experimental factors for trait-driven exploration.
Open Targets Platform opentargets/ Prioritised disease associations for therapeutics. Nodes: `Disease`
Relations: `ASSOCIATED_WITH`, `STUDIES_DISEASE`		 Processed via process_diseases.py with CSV inputs.
Biomarker collections biomarkers_data/, metabolite_data/ Links metabolites and proteins to disease biomarkers; includes COVID-19 markers. Relations: `IS_A_BIOMARKER_OF`, `METABOLITE_ASSOCIATED_WITH` Scripts rely on `covid_markers.txt` and curated CSVs.
IntAct intact/ Protein-protein interactions with curated vs compiled distinction. Relations: `CURATED_INTERACTS_WITH`, `COMPILED_INTERACTS_WITH`, `ACTS_ON` Supports exploration of interaction evidence strength.
Clinical Trials (completed + failed) data/ClinicalTrials_*.csv Outcomes and metadata for Phase I–III trials to augment indication evidence. Available for analytics or to extend ETL scripts. CSV-based; not yet fully integrated into Neo4j by default scripts.
Mol2Vec embeddings embed/ Generates molecular embeddings (e.g., 300-dim vectors) for feature enrichment. Outputs pickled models under data/model_300dim.pkl. Useful for graph ML tasks or bag-of-features creation.
PrimeKG connectors prime_kg/ Conversion utilities to ingest PrimeKG datasets into Neo4j or Nebula Graph. CSV outputs with ID remapping helpers. Supports custom expansions beyond default MedKG scope.
Visual analytics scripts visualize/ Plotting utilities for training/validation metrics. Produces figures under metrics/. Use alongside metrics/*.csv for dashboard generation.

Stewardship guidelines

Licensing

Respect licensing terms for proprietary datasets (DrugBank, TTD). Scripts assume you have legal access to required exports.

Provenance

Source metadata (IDs, definitions, citations) is preserved inside node properties to retain attribution.

Refresh cadence

Schedule ETL refreshes when upstream datasets release new versions. Many scripts can be adapted for incremental updates.
